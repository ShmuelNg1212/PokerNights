# Study: UI revamp, where people struggle and what looks unfinished

Date: 2026-10-31. Mode: design, with some technical work. Request: find where a person has difficulty navigating or doing the core flows. Make the app more dynamic, fluid, clean and beautiful.

## Method

- A fresh host walked the app in headless Chrome at 390 × 844 with touch emulation: sign up, first group, first table, new session, players, open, start, one rebuy, end, count, cash out, finalize, close, mark paid. The database started empty. Each tap and each field was recorded.
- 39 further captures cover seeded states as a host, a player and at 1280 px.
- Tap-to-screen time was measured at 4× CPU slowdown and 1.6 Mbps with 150 ms latency, against a local server.
- The source was read for each finding below.

Limits:

- This was one reviewer. It is not the two-agent `/impeccable critique`; that runs at rendezvous.
- Headless Chrome is not Safari on an iPhone. Feel, view transitions and the real keyboard need a phone.
- The seeded group has 17 open sessions and very long names, so its page heights are too large. Heights below come from the fresh walk unless marked "seeded".
- The first load over a phone network was not measured, because the service worker served the files.

Evidence captures are in [the assets folder](1793431816_ui_revamp_assets/). All data is synthetic.

## Conclusion

Keep The Rack. The identity is distinct and fits the room. The set in play, the count rows, the number keys, the review page and the who-pays-whom rows are good. Speed is not the problem.

The problems are in three places:

1. **Too many steps between the screens that work.** Setup and the end of a game pass through pages and confirmations that a host at a table does not need.
2. **Pages that grew by addition.** Group settings, New session, the session page and the set checklist each stack everything at one level.
3. **Feedback that repeats and motion that stops at the page edge.** A success can show four signals at once, while the largest moment in the app, the start of a game, is a 180 ms fade.

## Findings: navigation and core flows

Severity: **P1** causes real difficulty, **P2** is an annoyance with a workaround.

### First game

- **P1. A new group sends the host away to make a table.** "A session needs a table" leads to Group settings. After Add table the page stays there, with a toast and no next step. The host must find the Sessions tab, then New session. A home game has one table, and the concept means nothing yet. ([capture](1793431816_ui_revamp_assets/w-05-table-added.jpg))
- **P2. The home-screen sheet arrives before anything has happened.** It covers "Start your first group" straight after sign-up. PRODUCT.md asks for this timing, so changing it is a human decision. ([capture](1793431816_ui_revamp_assets/w-02a-install.jpg))

### Starting a game

- **P1. New session is one long form.** It has 17 controls and Create is at 1,612 px. With a preset chosen, the stakes are already right, but the host still scrolls past all of them. Without a preset, five required number fields start empty, even when the group played last week. ([capture](1793431816_ui_revamp_assets/h-06-new-session.jpg))
- **P1. Create session lands on a page that promotes the wrong thing.** The bone primary is Announce to the group. The way to the game is a secondary button, Open set 1. Seeded sessions with players show two bone primaries. ([capture](1793431816_ui_revamp_assets/w-08-session-created.jpg))
- **P1. On an open set, setup hides the table.** The checklist and the host dock leave room for one player row. Finished steps keep their full height and their buttons. ([capture](1793431816_ui_revamp_assets/w-13-open.jpg))
- **P2. Open and Start are two steps for a host whose players have no login.** The state machine allows `start` only from `open` (`games/services.py:303`). Open matters only when players will join for themselves.
- **P2. Draft repeats itself.** Add appears in the checklist and again as Add players in the dock. An empty "Players, 0 · 6 seats free" heading sits under a step that says "Nobody yet".
- **P2. Home has no New session.** The captured host card has Open the table and a gear, so a new game starts two screens away.

### End of a game

- **P1. Eight taps from typed counts to who pays whom, with the books already balanced.** Confirm 4 counts, Cash out counted players, Cash out 4 players, Finalize results, Finalize set 1, Settle up, Close session and settle up, then close the recap. Three of these confirm a fact the screen already states.
- **P1. The recap covers the answer.** "Close session and settle up" opens a sheet over the transfer list, which is what the button promised. A player who opens the page once to see what they owe meets it too. It opens once per person per browser. ([capture](1793431816_ui_revamp_assets/w-25-closed-first.jpg), [the page under it](1793431816_ui_revamp_assets/w-26-closed.jpg))
- **P2. Two buttons confirm the counts.** Confirm all counts sits in the page and Confirm 4 counts in the dock. ([capture](1793431816_ui_revamp_assets/w-18b-keys-closed.jpg))
- **P2. Results are not ranked.** Set and session results follow first appearance, so a reader scans for the winner. The recap already ranks them. Each row on the final set also takes about 155 px, because Details has its own line. ([capture](1793431816_ui_revamp_assets/w-23-final.jpg))

### Finding things

- **P1. Group settings holds everything.** Players, Invite players, Tables, Presets, Chip presets, Rake, Rename and Manage share one column. A new group's page is already 2,798 px. With a real roster, Invite sits under every player row, and each row carries its own "Manage {name}" line. Players are a daily destination, but they are filed under "settings". ([seeded capture](1793431816_ui_revamp_assets/h-04-group-settings.jpg))
- **P1. "Open" means four different things.** Open the table and Open set 1 go somewhere. Open for players changes a state. "Open" is a state badge, and "More open sessions" and "Session open" mean not closed. The next action is ambiguous at the moment that matters.
- **P2. Stats puts three rows of filters before the board.** The fifth sort, Sessions, sits past the screen edge with no cue. ([capture](1793431816_ui_revamp_assets/h-03-group-stats.jpg))
- **P2. The way back differs by page.** Most pages have the header's back arrow. Eleven templates instead keep the brand in the header and a small text link in the page, including New session and Add players. The cash-out review uses the header. Depth is hard to learn when the control moves.
- **P2. New session sits below the cards on the Sessions tab.** It moves down as sessions accumulate.

## Findings: wrong or unclear

- **Wrong word.** Start the set marks every player "Rebuy added", though these are first buy-ins. Any first buy-in does the same. `static/js/changes.js:49` treats every rise in the buy-in count as a rebuy. ([capture](1793431816_ui_revamp_assets/w-14-playing.jpg))
- **Feedback repeats.** After Confirm 4 counts, the screen shows a brass box per row, a green tick per row, a brass box on "4 of 4", a new dock message and a toast. ([capture](1793431816_ui_revamp_assets/w-19-confirmed.jpg))
- **Toasts cover the work.** A success toast is two lines tall, carries a 48 px Dismiss button and stays 6 seconds (`static/js/toasts.js:51`). In the walk one covered a count button, one a player row, one a result and one a section heading.

## Findings: clean and beautiful

- **Everything is framed.** Panels hold rows, rows hold bordered buttons, and every button has a hard underside. On the session page, stacked panels and equal-weight buttons leave no clear first read.
- **Heads repeat and crowd.** "Session: Rosa kitchen" sits directly above "Rosa kitchen". The title starts about 15 px under the header rule. "Saturday, October 31, 2026 · No-Limit Hold'em" repeats on each state of the page.
- **Group head uses a third of the screen** before any session appears.
- **Brass boxes are square** on text lines such as "4 of 4", while the rest of the system is round.
- **Stacked tokens clip their initials.** "AE AL AN BA" lose letters on Home and on session cards.
- **Details reads as a stray heading.** It is bold, bright and alone on its line.
- **Small text.** The Sessions tab has 65 text elements under 13 px in the seeded capture. That is hard to read in a dim room.
- **Open from TODO.** Chip k6 initials measure 3.8:1. Hairlines curl at both ends of rounded rows, on the set page as well as on Stats.

## Findings: dynamic and fluid

The foundation is strong and should be reused: presets in `static/js/motion.js`, depth-aware screen changes, the sheet, press feedback, the pot's roll, row arrivals. The gaps:

- **The set's state changes are 180 ms fades.** Start the set turns a neutral panel into felt with no sense of an event. This is the largest moment in the app, and it is not a money figure, so it can move.
- **52 native disclosures open with a snap.** `app.css` has no `::details-content` or `interpolate-size` rule. "More host controls" is the exception, with its own script.
- **Screens do not share elements.** A tapped session card disappears and its name appears again in the head. Only the header, the tabs and the front door carry across a change.
- **The checklist does not visibly advance.** A finished step changes in place. It could tick and fold, which also fixes the room problem above.

## Boundaries

Keep these unchanged:

- Money figures appear at their accepted value. Only the pot's digit roll is allowed.
- Success shows only after the server accepts.
- Typed values survive live updates.
- Writes stay in `services.py`. Records stay append-only.
- 48 px targets, reduced motion and the no-JavaScript paths stay.
- No front-end framework. Watermelon UI is React, so it is not used. Motion is already vendored, so `motion-plus` is not needed.

## Decisions for the human

These change product intent, so they go to the plan's OPEN QUESTIONS: merging the end-of-set steps, merging Open and Start, an inline first table, the recap's automatic opening, the home-screen sheet's timing, a Players tab, and the wording that replaces "open".

## Addendum, 2026-10-31: Home and New session

The finding "Home has no New session" is true only while a session is open. An idle group's card offers New session (`web/home.py:170`). The repeat game on an idle group is therefore 7 taps, not 8, plus one tick per player and the scroll. The P2 stands only for a host who has another session open, which is rare, so the plan has no task for it.
