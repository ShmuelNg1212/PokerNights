# Seat draw before a set starts: plan

Status: approved 2026-10-11 ("apporved"); all six decisions as recommended. Built and released. Date: 2026-10-11, Asia/Manila. Study: [Seat draw before a set starts](../study/1791717120_seat_draw.md).

## Outcome

On an open set the host can draw seats before starting. Every phone on the set page watches the draw pick the dealer, the winner (or the host for them) taps a seat on a drawn table, and everyone is dealt to their seat clockwise in the drawn order. The table then stays on the set page. The draw is optional: Start the set works without it.

Mode: Operate, with one Experience moment. Visual authority: the built Rack in DESIGN.md; no new colour, font or raster file. Built with the impeccable and motion skills and the Motion documentation server.

## Behaviour

| Moment | What happens |
|---|---|
| Open set, two or more players | "Get this set ready" gains an optional step between Open for players and Start the set: **Seat draw**. The host's menu gains a quiet **Draw seats** button under Start the set |
| Host taps Draw seats | The server shuffles the players at the table. The first is the dealer; the others are 1, 2, 3… seats clockwise. The draw stage opens on the host's phone at once and on every other phone on the set page within a few seconds |
| The draw plays (about 4 seconds) | See Motion. It ends on "{Name} has the dealer seat" |
| Choosing | Every seat on the drawn table is free. The winner and the host can tap one; the others read "{Name} is choosing a seat" |
| A seat is tapped | The dealer is placed there with the dealer disc, then the others are dealt clockwise, each with their first-hand position: small blind, big blind, under the gun, middle, hijack, cutoff. The viewer's own seat is marked "You" |
| After that | The stage has one button, "Done". The set page shows a small table: who sits where, who deals first. Tapping it opens the full table again |
| Start the set with a draw that has no seat chosen | The dealer is seated at the top seat. Start never waits for the draw |
| Draw again (host, before the start) | Asks once. The earlier draw is kept as replaced in the set log |
| A player joins or is taken off before the start | The draw is marked out of date: "The table changed. Draw again." The table is hidden until then |
| A player joins after the start | They have no seat. The host taps "Seat {name}" and then the gap between two players |
| A player leaves during play | Their seat stays, shown as away |
| A phone opens the set page later | It sees the finished table. "Watch the draw" replays it |
| Next set of the session | No seating; it can have its own draw |
| Reduced motion | The stage shows each result still, in three steps |
| No JavaScript | Draw seats and the seat choice are ordinary forms; the result is a list in seat order |
| `SEAT_DRAW=False` | No step, no button, no table; the services refuse |

## Motion

All movement is `transform` and `opacity`, through Motion with the existing presets plus two new ones written for this. Any tap skips to the end of the current part. Nothing waits for an animation.

1. **The table arrives** (400ms). The rail draws around the felt; the players' chip tokens are set down around it in join order, staggered.
2. **The draw** (about 3 seconds). The brass dealer disc runs around the ring of players, fast, then slower, each pass lighting the token under it; it overshoots the winner by one seat and springs back. The other tokens dim.
3. **The winner** (600ms). Their token lifts to the middle of the table with their name and "has the dealer seat". The seats empty and each free seat breathes once in turn to say it can be tapped.
4. **The seating** (about 1.8 seconds). The winner's token flies to the tapped seat and the disc lands beside it. The others leave the middle one at a time, 120ms apart, clockwise, each on a short arc to its seat; its position name fades in as it lands. The viewer's seat gets its ring last.
5. **The small table on the set page** arrives once with `arrive`; later updates do not move it.

## Decisions for the human

Approving accepts the recommendations unless you say otherwise.

1. **The draw runs about 4 seconds and the seating about 2,** against DESIGN.md's rule that a signature moment ends within 900ms. Recommended as a recorded exception for this one ceremony: it is asked for, optional, skippable by a tap, and plays once per phone. Say a shorter length if you prefer.
2. **A drawn table, no cards and no picture.** The rail, the felt and the chip tokens the app already has, with a dealer disc. Recommended so it stays inside "no casino imagery".
3. **Positions are shown for the first hand only.** During play the table shows seats and who dealt first, because the app does not follow the button.
4. **A change of players before the start asks for a new draw** instead of patching the old one. Recommended: a patched draw is not a draw.
5. **Each set has its own draw.** Seats are not carried to the next set. Say if "Keep these seats" should be offered on a next set.
6. **A switch, `SEAT_DRAW`, on by default.**

## Implementation

Branch `feat/seat-draw` from `main`. Tests first for the server part.

1. **Models (`games`), one migration.**
   - `SeatDraw`: set, number, `is_current`, `stale` mark, who drew and when, `request_id` (unique), the dealer's chosen seat (empty until chosen), who chose and when with its own `request_id`, and the replaced mark. One current draw per set by constraint.
   - `SeatPlace`: draw, participant, distance clockwise from the dealer (0 is the dealer). Unique per draw on participant and on distance. A late player's place is a new row at the chosen gap, with later distances moved up by a new draw revision, so no row is edited.
2. **Services (`games/services.py`).** `draw_seats`, `choose_seat` (the dealer's own member or a host), `seat_late_player`. Each locks the set, checks the state and the role, records to the audit log and raises the set's version. Adding or withdrawing a player before the start marks the current draw stale. Starting the set fixes an unchosen seat.
3. **Queries.** `seating(session)`: the seats in order with member, distance, position name and the dealer mark, in two queries, added to the set page's snapshot.
4. **Views and addresses (`web`).** `s/<id>/draw/`, `s/<id>/draw/seat/`, `s/<id>/draw/late/`; each resolves through membership and answers in place.
5. **Templates.** The optional step and the host's button; `_seat_table.html` (the table, seats placed by percentages a template tag works out, so it is right without scripts); the stage's data on the live region.
6. **`static/js/seats.js`,** registered with `page.js`: owns the stage (a dialog outside the live region), plays each part from the snapshot, remembers a played draw per browser, sends the seat choice, and asks the server every 1.5 seconds while a draw waits for a seat (two minutes at most). `motion.js` gains the two presets.
7. **CSS.** The table, seats, disc, stage and the small table, at 320, 390 and from 900px; reduced motion.
8. **Design passes.** impeccable for the stage and the small table (shape before, critique and polish after, on captures at 320, 390 and 1280px); the motion skill and the Motion documentation server for the springs, the stagger and a performance audit of the stage.
9. **Tests.**
   - Django: the draw holds every player once and one dealer; positions for 2, 3, 6, 9 and 12 players; a replayed request draws nothing twice; only a host draws; only the dealer or a host chooses; a second choice is refused; a draw is refused outside an open set and with fewer than two players; joining and withdrawing mark it stale; drawing again keeps the old one; start fixes an unchosen seat; a late player's seat; a non-member gets 404; the switch; the set page and its snapshot stay within their query budgets.
   - Browser (`seat_draw.mjs`, new): host and two players side by side: the stage opens on all three; the disc lands on the server's winner; only the winner and host can tap; the seating matches the server on every phone; skip by tap; a later phone sees no replay; Draw again; stale after a join; the late player; reduced motion; no JavaScript; 48px seat targets; 2, 6 and 12 players at 320, 390 and 1280px; frame timing with the processor slowed four times; no script error. `table.mjs` reruns.
   - Both suites: SQLite and PostgreSQL.
10. **Documents.** Wiki (features, architecture, deployment for the switch), PRODUCT.md (seating is built), DESIGN.md addendum with the recorded exception, browser README, TODO.md with the phone checklist.

## Out of scope

- Following the dealer button hand by hand.
- Moving a seated player, or swapping two seats.
- Carrying seats to the next set (decision 5).
- Sound and vibration.

## Acceptance

1. A host draws on an open set; within a few seconds every phone on the set page plays the same draw and names the same dealer.
2. The winner, or the host, taps a seat; every phone seats the same players in the same places, clockwise in the drawn order, with first-hand positions.
3. Start the set works with no draw, with a draw and no seat chosen, and with a finished draw.
4. The seating is on the set page during play; a late player can be seated by the host.
5. A tap skips the animation; reduced motion and no JavaScript show the same result.
6. Both test suites pass.

## Release

Kept local on its branch until you say to push. One migration that only adds two tables. The first response to trouble is `SEAT_DRAW=False`.

## Progress

2026-10-11: Approved. Built on `feat/seat-draw` from `main`. While it was being built the human said "push", then "ok push when you are done building the feature."

Changes from the plan:

- **One Draw button, on the step.** The plan also put a "Draw seats" button in the host's menu. It made the menu 283px tall against the set page's measured limit of 260px, so it was removed.
- **A late player is seated with "Seat {name} after {player}"** (a list and a button), not by tapping a gap on the table.
- **A late player's place is one new row** at the midpoint between two ranks. The plan spoke of a new draw revision; ranks 1024 apart make that unnecessary.
- **"Has a draw" rides on the page's existing query.** A set without a draw costs no extra query; one with a draw costs one.
- **Closing the stage counts as having watched.** Found in the browser: a stage closed part-way came back at the next update.
- **A seat chosen while a phone is still watching the draw** is picked up when its draw ends. Found in the browser: that phone never played the seating.
- **On a screen under 700px tall with nine or more players the position badges are left out** on the stage; the names stay and the positions are in the list on the page.
- **The stage sits inside `#table-sheets`.** In the body it was removed when a form was answered in place.
- **One existing browser check changed:** `table.mjs` expects the optional step among the steps.
- The impeccable and motion skills' rules were applied from their earlier loading in this session; the Motion documentation server was searched for stagger and sequence guidance. No separate critique run or MotionScore audit was made.
