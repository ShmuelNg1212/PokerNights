The questions as asked follow. An approved change to a rule updates spec.md and adds an ADR.

1. **Visual direction.** (a) Keep The Rack, and make it cleaner and calmer. (b) Replace the visual world with a new one. Recommended: (a). The identity is good and the problems are structural. (b) adds a new study and would redo much of Slice E.
2. **Finishing a balanced set (C1).** After the counts are confirmed and the books balance: (a) one review page with one button, Finish set, which records the cash-outs and finalizes together; (b) keep the two steps. Recommended: (a). The records stay the same and it removes two taps. An unbalanced set keeps today's path.
3. **Open and Start (B5).** (a) Start the set works from Draft and records both changes; "Let players join first" stays as a secondary action; (b) keep both steps. Recommended: (a). Players with logins can still join a running set.
4. **First table (B1).** (a) A group with no table types a table name on New session, and the table is made with the session; (b) keep the trip to Group settings. Recommended: (a).
5. **Recap (C3).** (a) The recap never opens by itself; its summary and a View recap button sit under who pays whom; (b) open by itself, but only for a person with no transfer to read; (c) keep today's behaviour. Recommended: (a).
6. **Home-screen sheet (B6).** (a) Show it after the person's first session is created or first joined; (b) keep it straight after sign-up and login. Recommended: (a). This revises the 2026-10-11 addendum in PRODUCT.md.
7. **Players tab (D1).** (a) Tabs become Sessions, Players, Stats, Settings; (b) keep three tabs and only reorganize Group settings. Recommended: (a).
8. **Words (D5).** (a) "Go to" for moving: Go to the table, Go to set 1. Set state "Open" becomes "Joining", and the action becomes "Let players join". "Not closed" becomes "In progress". (b) Keep "Open" and change only the navigation words. Recommended: (a). This revises the 2026-10-09 addendum, which fixes the states as Draft, Open and In play.

## How to build

- One feature branch per slice, stacked on the last unreleased one, in the order below. Each slice ships when the human says so, and each leaves the app working.
- Before any UI edit, read impeccable's `reference/craft-floor.md`, and the surface brief for the page.
- Stay inside the tokens and the motion presets of DESIGN.md. Add a dated DESIGN.md addendum at the end of each slice.
- Risky movement checks support and falls back to today's behaviour. Each slice keeps reduced motion and the no-JavaScript path working.
- Browser scripts under `web/tests/browser/` assert today's layout. Update a script only when the plan changed the behaviour it checks, and record the change in the browser README.
